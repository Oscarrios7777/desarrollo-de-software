Punto de partida

Introducción

El desarrollo de software es el proceso sistemático de concebir, diseñar, construir, probar y mantener programas que resuelven necesidades reales de personas y organizaciones. Lejos de reducirse a "escribir código", implica decisiones de diseño, trabajo colaborativo, gestión de calidad y una mejora continua a lo largo de todo el ciclo de vida del producto.

En un país como el Perú, donde la transformación digital avanza en banca, retail, educación y salud, comprender cómo se construye el software es una competencia esencial para cualquier profesional de tecnología. Este sitio recorre tres subtemas fundamentales que explican cómo se organiza, con qué se escribe y cómo se controla la evolución de un sistema.

1. Arquitectura

La estructura que define cómo se organizan y comunican las piezas del sistema.

2. Lenguajes y paradigmas

Las herramientas y estilos de pensamiento con los que se expresa la solución.

3. Versionamiento Git

El historial que permite trabajar en equipo sin perder el control del código.

Objetivo del trabajo: explicar de forma clara y fundamentada los conceptos base del desarrollo de software, integrando definiciones, ejemplos prácticos y comparaciones que evidencien su aplicación profesional.
Subtema 01

Arquitectura de software

La arquitectura de software es el conjunto de decisiones estructurales de alto nivel que determinan cómo se divide un sistema en componentes, cómo se relacionan entre sí y qué reglas gobiernan esa interacción. Es, en esencia, el plano del edificio: corregirla tarde resulta costoso, y acertarla temprano facilita todo lo demás.

¿Por qué es importante?

  • Escalabilidad: permite que el sistema soporte más usuarios sin reescribirse.
  • Mantenibilidad: un cambio afecta a una parte acotada y no a todo el programa.
  • Calidad: favorece atributos como seguridad, rendimiento y disponibilidad.
  • Trabajo en equipo: distintos equipos pueden avanzar en módulos distintos a la vez.

Estilos arquitectónicos más usados

EstiloIdea centralVentajaDesventaja
MonolíticaToda la aplicación en un solo bloque desplegable.Simple de desarrollar y desplegar al inicio.Difícil de escalar y mantener cuando crece.
Cliente–ServidorEl cliente solicita, el servidor procesa y responde.Centraliza datos y seguridad.El servidor puede volverse cuello de botella.
Capas (N-tier)Presentación, lógica de negocio y datos separadas.Orden y separación de responsabilidades.Puede añadir latencia y rigidez.
MicroserviciosServicios pequeños e independientes que se comunican por APIs.Escalado y despliegue independientes.Mayor complejidad operativa.
Orientada a eventosLos componentes reaccionan a eventos publicados.Alto desacoplamiento y respuesta en tiempo real.Difícil de depurar y trazar.

Ejemplo aplicado: arquitectura en capas

Presentación (UI)→Lógica de negocio→Acceso a datos→Base de datos

En una tienda virtual, la capa de presentación muestra el catálogo, la capa de negocio valida el stock y calcula el total, la capa de datos consulta la base y devuelve la información. Si mañana cambia el diseño visual, la lógica de negocio permanece intacta.

Patrones complementarios: MVC (Modelo–Vista–Controlador), MVVM y Arquitectura Hexagonal son formas concretas de organizar el código dentro de estos estilos, siempre buscando bajo acoplamiento y alta cohesión.
Subtema 02

Lenguajes de programación y paradigmas

Un lenguaje de programación es un sistema formal de notación que permite expresar instrucciones que una computadora puede ejecutar. Un paradigma, en cambio, es el enfoque mental con el que se estructura la solución: no es el idioma, sino el estilo de razonamiento.

Clasificación de los lenguajes

  • Por nivel: bajo nivel (Ensamblador, cercano al hardware) y alto nivel (Python, Java, cercanos al lenguaje humano).
  • Por ejecución: compilados (C, Go), interpretados (Python, JavaScript) o híbridos (Java, C#).
  • Por tipado: estático (Java, TypeScript) o dinámico (Python, PHP).

Principales paradigmas

Imperativo / Estructurado

Describe paso a paso cómo hacerlo, con secuencias, condicionales y bucles. Ej.: C, Pascal.

Orientado a objetos (POO)

Modela el mundo con objetos que combinan datos y comportamiento. Pilares: abstracción, encapsulamiento, herencia y polimorfismo. Ej.: Java, C#, Python.

Funcional

Se basa en funciones puras e inmutabilidad, evitando efectos secundarios. Ej.: Haskell, Scala, JavaScript moderno.

Lógico

Se declaran hechos y reglas; el motor deduce la respuesta. Ej.: Prolog.

Declarativo

Expresa qué se quiere obtener, no cómo. Ej.: SQL, HTML.

Concurrente

Organiza tareas que se ejecutan en paralelo de forma segura. Ej.: Go, Erlang, Rust.

Un mismo problema, dos paradigmas

# Imperativo: describo el "cómo"
numeros = [1, 2, 3, 4, 5, 6]
pares = []
for n in numeros:
    if n % 2 == 0:
        pares.append(n)

# Funcional: describo el "qué"
pares = list(filter(lambda n: n % 2 == 0, numeros))

No existe el "mejor lenguaje": existe el más adecuado según el problema, el rendimiento requerido, el ecosistema disponible y la experiencia del equipo.
Subtema 03

Versionamiento con Git

Git es un sistema de control de versiones distribuido creado por Linus Torvalds en 2005. Registra cada cambio del proyecto en una línea de tiempo llamada historial, permitiendo volver a cualquier punto anterior, comparar versiones y trabajar en equipo sin sobrescribir el trabajo ajeno.

Es importante distinguir a Git (la herramienta que corre en tu computadora) de plataformas como GitHub, GitLab o Bitbucket, que alojan repositorios en la nube y añaden colaboración, revisión de código e integración continua.

Conceptos clave

Repositorio

Carpeta del proyecto con todo su historial de cambios.

Commit

Fotografía de los cambios en un momento dado, con autor, fecha y mensaje.

Rama (branch)

Línea paralela de trabajo para desarrollar sin afectar la versión estable.

Merge

Fusión de una rama con otra para integrar el trabajo terminado.

Push / Pull

Enviar cambios al repositorio remoto o traer los de los demás.

Conflicto

Ocurre cuando dos personas editan la misma línea; se resuelve manualmente.

Flujo de trabajo básico

Working Directory→ add →Staging Area→ commit →Repositorio local→ push →Repositorio remoto

Comandos esenciales

git init                      # crear un repositorio local
git clone <url>               # copiar un repositorio remoto
git status                    # ver el estado de los archivos
git add .                     # preparar los cambios
git commit -m "mensaje claro" # guardar una versión
git branch nueva-funcion      # crear una rama
git checkout nueva-funcion    # cambiar de rama
git merge nueva-funcion       # fusionar ramas
git pull / git push           # sincronizar con el remoto
git log --oneline             # revisar el historial

Buenas prácticas

  • Escribir mensajes de commit descriptivos y en tiempo presente.
  • Hacer commits pequeños y frecuentes, no uno gigante al final.
  • Mantener la rama principal siempre estable y trabajar en ramas por funcionalidad.
  • Sincronizar antes de empezar a trabajar para evitar conflictos.
  • Usar un archivo .gitignore para excluir archivos temporales o credenciales.
Modelos de ramificación: Git Flow (ramas main, develop, feature, release y hotfix) y GitHub Flow (main + ramas de funcionalidad con Pull Request) son los esquemas más utilizados en la industria.
Cierre

Conclusiones

  • La arquitectura de software define la estructura del sistema y condiciona su escalabilidad, mantenibilidad y calidad a largo plazo.
  • Los lenguajes y paradigmas son herramientas complementarias: elegir bien depende del problema, no de la moda, y dominar varios paradigmas amplía la capacidad de resolver.
  • Git convierte el desarrollo en un proceso trazable y colaborativo, reduciendo el riesgo de pérdida de información y facilitando el trabajo en equipo.
  • Integrar los tres subtemas permite construir software profesional, ordenado, sostenible y alineado con las prácticas actuales de la industria.
